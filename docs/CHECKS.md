# Check catalogue

Each check has an id of the form `category.topic.detail`. The Ver column
is the release a check first ships in. Rows marked (planned) are not built yet.
Thresholds are defaults and can be changed in `wp-doctor.json`.

## Performance and database (`perf.*`)

| Id | Detects | Default severity | Needs | Ver |
| --- | --- | --- | --- | --- |
| `perf.autoload.size` | Total size of `wp_options` rows that WordPress loads on every request (`autoload` of `yes`, `on`, `auto`, `auto-on`). Main-site table only. Thresholds are rule-of-thumb defaults, not measured per site; the finding says so | warning above 1 MiB (1048576 bytes), critical above 3 MiB; skipped when the table has no autoloaded rows | DB | 0.1 |
| `perf.autoload.top` | The 10 largest autoloaded options (same autoload values as `perf.autoload.size`), listed by name and size in bytes, largest first. One finding whenever the table has autoloaded rows; skipped when it has none | info | DB | 0.1 |
| `perf.autoload.orphaned` | Autoloaded options above 10 KiB (50 largest examined) whose name prefix (text before the first `_` or `-`) matches no installed plugin, must-use plugin or theme folder and is not a known core prefix (`{table prefix}user_roles` is core too). Likely leftovers; plugins whose option prefix differs from their folder name are false positives. Symlinked plugin and theme folders count by name. A missing `mu-plugins` or `themes` directory is fine; one that exists but cannot be listed fully, or leaves the site root, skips the check, as does a missing plugins directory. Threshold and core prefix list are unverified defaults | warning | DB, FS | 0.1 |
| `perf.objectcache.missing` | No `object-cache.php` drop-in in the content directory. A drop-in that is a symlink inside the site root counts as present, a broken one as not loading. Skipped when the drop-in is a symlink that leaves the site root, or when `WP_CONTENT_DIR` cannot be resolved to a directory inside the site root | warning | FS | 0.1 |
| `perf.transients.expired` | Expired transients (`_transient_` and `_site_transient_`) still stored in the options table, counted by their timeout rows against the scan time, with the size of their values. Transients held by an external object cache are not in the database and are not counted | warning above 5000 rows | DB | 0.1 |
| `perf.cron.overdue` | Scheduled events more than 1 hour late, read from the `cron` option without `unserialize`. Notes `DISABLE_WP_CRON` when it is true, and says so when its value could not be read. Same skip rules as `perf.cron.duplicates`, and the same warning for a cron option that is not in the shape WordPress writes | warning | DB | 0.1 |
| `perf.cron.duplicates` | The same hook with identical arguments scheduled many times (likely runaway rescheduling). A hook scheduled with different arguments, such as one event per post, is not counted. Reads the `cron` option without `unserialize`; objects and repeated values inside event arguments are skipped without being built, while the levels above them must be arrays. Skipped when the option is missing, above 16 MiB, or holds more than 50000 distinct events. A value that is not a serialized array of timestamps, hooks and events (an object, a text key at the top, truncated data) is a warning that WordPress likely cannot run its schedule, with the reason, the option size and the byte where reading stopped. The 50 is a rule-of-thumb default, and the finding says so | critical above 50 copies; warning when unreadable | DB | 0.1 |
| `perf.cron.disabled` | `DISABLE_WP_CRON` set to a true value in `wp-config.php`, so page loads no longer run scheduled events and a system cron job must. Whether such a job exists cannot be seen from the site's files; `perf.cron.overdue` reports events that are late. Skipped when `DISABLE_WP_CRON` is computed, or is not set while `wp-config.php` loads code that was not read | info | FS | 0.2 |
| `perf.tables.largest` | The 10 largest tables that carry the site's table prefix, by data plus index size from the server's table statistics (estimates for some engines) | info | DB | 0.1 |
| `perf.tables.bloat` | Tables above 100 MiB whose name (without the prefix) ends in `log`, `logs`, `session` or `sessions`, or starts with `actionscheduler_`. Name test and size are unverified defaults. Post revisions live inside the posts table and are not measured | warning | DB | 0.1 |
| `perf.revisions.count` | More than 10000 rows of type `revision` in the posts table (unverified default). Evidence gives the number of posts with revisions, the five posts with the most, and what `WP_POST_REVISIONS` keeps, read as `wp_revisions_to_keep()` reads it | warning | DB | 0.2 |
| `perf.tables.engine` | Base tables with the site's prefix that use the MyISAM engine, which locks a whole table for each write and has no crash recovery. Views and tables without the prefix are not read. Skipped when no table carries the prefix or more than 10000 do | info | DB | 0.2 |
| `perf.slowquery.indexcheck` | Joins between columns of mismatched type or collation (cannot use an index) found in `EXPLAIN` of provided queries | warning | DB | 0.3 (planned) |

## Disk and logs (`disk.*`)

| Id | Detects | Default severity | Needs | Ver |
| --- | --- | --- | --- | --- |
| `disk.debuglog.size` | The debug log above 100 MiB, critical above 1 GiB. The file is `debug.log` in the content directory, or the file `WP_DEBUG_LOG` names when it resolves to a path inside the site root (a literal, or `__DIR__`, `dirname( __FILE__ )` or `ABSPATH` plus a literal). A log outside the root, a log that is a symlink or a broken symlink, a `debug.log` that is a directory, or a computed path skips with the reason | warning above 100 MiB, critical above 1 GiB | FS | 0.1 |
| `disk.errorlog.size` | `error_log` files anywhere under the site above 50 MiB. Skipped when nothing was found but the walk was incomplete: it stopped at the file limit, met an unreadable path or a symlink leaving the root, or every entry was excluded. A symlink leaving the root, such as uploads on shared storage, is named in the reason; excluding it with `--exclude` lets a clean site pass | warning | FS | 0.1 |
| `disk.leftovers.web` | SQL dumps (`.sql`, `.sql.gz` and similar) and copies of `wp-config.php` with a non-PHP ending (critical). Inside a plugin, must-use plugin, theme, `vendor` or `node_modules` directory a `.sql` counts only when it holds `INSERT INTO`, since shipped schema files hold no data; archives (`.zip`, `.tar`, `.gz`, ...) outside `wp-content/uploads`, backup copies (`.bak`, `.old`, `.orig`, `.save`, `.swp`, `.backup`, `~`), and copies of `wp-config.php` that keep `.php` (`wp-config-old.php`, `wp-config.old.php`, `wp-config-2024-05-01.php`), which run rather than download (warning). Precompressed pages that cache plugins write (`index.html.gz`, `app.js.gz`) are not archives. Archives in those code directories stay warnings, with evidence that counts them and says themes and plugins often bundle archives. `wp-config-local.php` and `wp-config-sample.php` are not copies. Which files the web server actually serves is not tested, so findings say "likely". Skipped when nothing was found but the walk was incomplete, as for `disk.errorlog.size`, with the same symlink reason and remedy | critical for dumps and config copies, warning for the rest | FS | 0.1 |
| `disk.uploads.size` | Total size and file count of the uploads directory, and the 10 largest entries at its top, such as year folders and folders plugins write there. Regular files only; symlinks are not followed, and one that leaves the root is named with the total marked incomplete. The directory is found as for `sec.uploads.php`, and the evidence says when `upload_path` could not be read. Skipped when the directory is missing | info | FS | 0.2 |
| `disk.cache.size` | A cache folder in the content directory above 1 GiB (unverified default): `cache` (WP Super Cache, W3 Total Cache and others), `litespeed` (LiteSpeed Cache) or `wpo-cache` (WP-Optimize). Evidence gives each folder's size and its five largest entries. A folder that is a symlink is not followed. Skipped when nothing is above the threshold but a folder could not be measured in full | warning | FS | 0.2 |

## Security and compromise indicators (`sec.*`)

| Id | Detects | Default severity | Needs | Ver |
| --- | --- | --- | --- | --- |
| `sec.users.admins` | Accounts with the administrator role (the newest 200; `list_truncated` when there are more), with registration dates, emails and post counts (info). Critical when 3 or more that are not allowlisted were registered within 24 hours of each other (unverified default); the finding says an import or site move gives the same pattern, and when a login matches a published indicator from `data/rogue-admin-indicators.json` (exact or prefix), or a soft indicator together with its documented email. Warning for an empty, invalid, placeholder (`example.com`, `.test`, `.local` and similar) or disposable-mail address (`data/disposable-email-domains.txt`), and for a soft indicator on an account that is both the newest and has no posts. The display name and website are not judged, since an account added in Users > Add New has the login as display name and no website. Info when one administrator is the only one on a different email domain, the newest, and has no posts. Allowlisted logins are listed but never judged by any rule. Every judgement says "likely" | info; warning; critical | DB | 0.1 |
| `sec.core.checksums` | Core files that differ from, or are missing compared with, the wordpress.org checksum for the installed version (critical); files inside `wp-admin` or `wp-includes`, and PHP files at the top of the core directory, that the release does not contain (critical in the core directories, warning at the top). When core is in a subdirectory, PHP files at the top of the web root are listed too, apart from the `index.php` that loads core. An `.htaccess`, `.user.ini` or `php.ini` inside `wp-admin` or `wp-includes` is reported as such a file; only `error_log` and `.DS_Store` are ignored there. `wp-content`, `readme.html`, `license.txt`, `wp-config-sample.php` and `wp-config-docker.php` are not compared. Core files that are excluded, behind a symlink leaving the root, unreadable, or above 64 MiB are listed as not compared, never as missing, and make the result incomplete. The locale is the package's `$wp_local_package` in `wp-includes/version.php`, else `en_US`. Skipped with `--offline` or when the checksums cannot be fetched | critical | FS, network | 0.1 |
| `sec.uploads.php` | PHP-executable files under `uploads/` (`.php`, `.php3`-`.php8`, `.phtml`, `.pht`, `.phps`, `.phar`), critical. An `.htaccess`, `.user.ini` or `php.ini` there that maps a handler or type to PHP, turns the PHP engine on, or sets `auto_prepend_file`/`auto_append_file`, critical ("likely"); a `.user.ini` or `php.ini` without such lines, warning. An `.htaccess` that only stops PHP running, as security plugins write, is not reported. The empty `Silence is golden` index.php stubs of 512 bytes or less are not reported. The directory is `UPLOADS`, else the `upload_path` option, else `wp-content/uploads`. A clean result is a skip when the walk was incomplete, a symlink inside uploads was not followed (each is listed), uploads holds no files, or `upload_path` could not be read without the database | critical; warning | FS, DB | 0.1 |
| `sec.uploads.disguised` | Files with image extensions whose first 1024 bytes contain `<?php` or `<?=`, or whose name has a PHP extension before the image extension (`x.php.jpg`, `x.php_.jpg`). Content test is a heuristic. Same directory and same skips as `sec.uploads.php`, and skipped when uploads holds no images | critical ("likely") | FS, DB | 0.1 |
| `sec.code.obfuscated` | `eval()`, `assert()` or `create_function()` whose argument comes from a decoder (`base64_decode`, `gzinflate`, `gzuncompress`, `gzdecode`, `str_rot13`, `strrev`, `hex2bin`, `convert_uudecode`) or from a string of 200 or more base64 or hex characters or 50 `\x` escapes, directly, through string functions such as `str_replace`, or through a variable assigned in the same file. Every `.php`, `.php3`, `.php4`, `.php5`, `.php7`, `.php8`, `.phtml` and `.pht` file under the root is read as tokens, never run, and so is `wp-config.php` when it sits above the root. An argument that is a comparison or a logical test is not counted, and a variable passed through any other call is not followed. Evidence gives each file, the line, and the functions involved. Skipped when nothing was found but some PHP was not read in full: a file larger than 4 MiB, an unreadable file, or a part of the tree the walk did not reach | warning ("likely") | FS | 0.2 |
| `sec.code.remotefetch` | `eval()`, `assert()`, `create_function()`, `include` or `require` whose argument is fetched from another server: `curl_exec`, the WordPress HTTP API, `fsockopen`, `stream_socket_client`, `download_url`, or `file_get_contents`, `file`, `fopen`, `fread`, `fgets` or `stream_get_contents` given a URL literal or decoded data, directly or through a variable assigned in the same file. An `include` or `require` of a URL literal counts too. Read and skipped like `sec.code.obfuscated` | critical ("likely") | FS | 0.2 |
| `sec.plugins.unknown` | PHP in the plugins directory that WordPress would not load as a plugin. WordPress reads a `Plugin Name:` header from the first 8 KiB of the `.php` files at the top of the directory and at the top of each folder in it, and passes over names that begin with a dot. Reported: a folder holding PHP (`.php`, `.php3`-`.php8`, `.phtml`, `.pht`) at any depth with no such header file, which includes a plugin nested one folder too deep; a dot-named folder holding PHP; a PHP file at the top with no header, apart from the empty `Silence is golden` index.php. A folder without PHP is not reported. Folder names are not judged, since many plugins' main files do not match their folders. Evidence gives each entry, the reason, its PHP file count and when the newest one changed. Skipped when `WP_PLUGIN_DIR` or `WPMU_PLUGIN_DIR` is set, and when nothing was found but a symlink was not followed, a header could not be read, or the walk was incomplete | warning ("likely") | FS | 0.2 |
| `sec.themes.unknown` | PHP in `wp-content/themes` that WordPress would not run as part of a theme. As WordPress does, a folder with a `style.css` is a theme, a folder without one is a folder of themes when its subfolders have one, and names that begin with a dot and `CVS` are passed over; a theme needs `index.php`, `templates/index.html` or `block-templates/index.html` unless its `style.css` has a `Template:` header. Reported: a folder holding PHP with no `style.css` in it or its subfolders, a theme holding PHP that lacks both a template and a parent, PHP in a folder of themes outside its themes, a dot-named or `CVS` folder holding PHP, and a PHP file at the top apart from the empty index.php. Theme directories that a plugin registers are not read. Evidence and skips as for `sec.plugins.unknown`, with `WP_CONTENT_DIR` outside the root as the moved-directory skip | warning ("likely") | FS | 0.2 |
| `sec.plugins.checksums` | Files in each plugin folder compared with the checksums wordpress.org publishes for the folder's slug and the `Version:` header of its plugin file, as `wp plugin verify-checksums` does: SHA-256 where published, else MD5, any listed hash accepted. A file whose hash differs is changed, a file the list does not name is added; `readme.txt` and `readme.md` are passed over, and missing files are not reported. `hello.php` is compared with the copy in the installed WordPress release and in the last release of each of the eight series before it, since updates leave it in place. Plugins wordpress.org does not publish (premium and custom ones, or a version it does not have), folders with no `Version:` header and other single-file plugins are listed as not checked; must-use plugins are not read. Skipped with `--offline`, when `WP_PLUGIN_DIR` or `WPMU_PLUGIN_DIR` is set, when no plugin is installed, and when nothing differs but a plugin could not be checked, a file could not be read, or the walk was incomplete | warning | FS, network | 0.3 |
| `sec.content.injected` | Posts containing script tags from unfamiliar hosts, or defacement markers in recent posts | warning | DB | 0.3 (planned) |
| `sec.recent.changes` | PHP files written in the last 7 days apart from the rest of their package. An install or update writes every file of a package within seconds, so a PHP file counts as written apart when fewer than half of the package's other files (of any type) were written within an hour of it. The packages are WordPress core (the top of the core directory, `wp-admin`, `wp-includes`), each entry at the top of the plugins, `mu-plugins` and themes directories, and for any other file its own directory, so a PHP file alone in a directory is listed when it is recent. The time used is the inode change time, which `touch` cannot set back, not the modification time an archive or a copy can keep; both are in the evidence. `wp-content/cache` and the empty `Silence is golden` index.php are passed over. The number of days is the `info` threshold. Skipped on Windows, where PHP reports the creation time; when every PHP file was written within one hour, as after a fresh install or a copy of the site; when `WP_PLUGIN_DIR` or `WPMU_PLUGIN_DIR` is set; and when nothing was found but the walk was incomplete | info ("likely") | FS | 0.2 |
| `sec.wpcron.persistence` | Scheduled events whose callbacks are not registered by any installed plugin or theme | warning | DB, FS | 0.3 (planned) |
| `sec.updates.outdated` | Plugins, themes and core with a pending update in the stored `_site_transient_update_*` data: in the options table on a single site, in `sitemeta` for the network named by `SITE_ID_CURRENT_SITE` (else 1) on a multisite network. A core offer counts when its response is `upgrade` or `autoupdate` and its version is newer than the installed one, once per version. As fresh as WordPress's last update check. Skipped when WordPress holds no update data in the database (an external object cache may hold it), naming `sitemeta` too when `MULTISITE` could not be read, and when `SITE_ID_CURRENT_SITE` could not be read | warning | DB | 0.1 |
| `sec.plugins.inactive` | Plugin folders and single-file plugins under `wp-content/plugins` that are not in `active_plugins`. Symlinked plugin folders count by name and are not followed. Names that begin with a dot, such as `.git`, are passed over as WordPress does. Skipped on multisite, when `MULTISITE` cannot be read, or is not defined while `wp-config.php` includes a file that was not read, and when the plugins directory could not be listed fully | info | DB, FS | 0.1 |

## Configuration and hardening (`config.*`)

| Id | Detects | Default severity | Needs | Ver |
| --- | --- | --- | --- | --- |
| `config.debug.enabled` | `WP_DEBUG` set to a true value in `wp-config.php`. WordPress reads `WP_DEBUG_DISPLAY` and `WP_DEBUG_LOG` only while `WP_DEBUG` is on, so they are shown as evidence (display defaults to on) and never judged alone. Whether the site is live is not known, so the finding says "likely". Skipped when `WP_DEBUG` is computed, or is missing while `wp-config.php` includes a file or calls `eval()` | warning | FS | 0.1 |
| `config.fileedit.enabled` | Neither `DISALLOW_FILE_EDIT` nor `DISALLOW_FILE_MODS` is set to true in `wp-config.php` (they could be set elsewhere, so "likely"). Skipped when either constant is computed, or is missing while `wp-config.php` includes a file that was not read | info | FS | 0.1 |
| `config.multisite.scope` | `MULTISITE` is true in `wp-config.php`: the database checks read only the main site's tables, so a clean report does not cover the other sites. Skipped when `MULTISITE` is computed or conditional, or not defined while `wp-config.php` includes a file that was not read | info | FS | 0.1 |
| `config.salts.default` | Any of the 8 keys and salts missing, empty, still the sample text, or sharing a value with another (critical). A value under 32 characters is likely guessable (warning); the WordPress generator gives 64. Values are compared and measured but never shown | critical; warning for short values | FS | 0.1 |
| `config.perms.wpconfig` | `wp-config.php` readable by others, or writable by group or others. Group read is allowed, so the fix, `chmod 640`, passes. Read in the web root or the core directory; skipped when it is above the site root | warning | FS | 0.1 |
| `config.perms.writable` | World-writable files and directories under the site root; symbolic links are skipped | warning | FS | 0.1 |
| `config.exposed.files` | At the top of the web root only, and of the core directory when core is in a subdirectory: `.git`, `.svn`, `.hg`, `.env` and `.env.*`, and PHP files that call `phpinfo()`, apart from the core root files such as `wp-login.php` (warning, "likely" reachable); `readme.html` (info, because it only shows the version). A symlink that leaves the root is judged by its name and not followed. Copies of `wp-config.php` are reported by `disk.leftovers.web` | warning; info for readme.html | FS | 0.1 |
| `config.php.version` | A PHP version past the end of security support, from a table of dates built into wp-doctor. The version comes from an `AddHandler`/`SetHandler`/`AddType` line in the site's `.htaccess` that names one (`ea-php74`, `php8.1`, `lsphp81`), which likely selects the web server's PHP; with such a hint, plugins whose `Requires PHP` header is above it are an info finding, and a hinted version in support skips rather than passes when a plugin folder could not be read fully. Without a hint the PHP that runs wp-doctor is judged, a version in support is skipped rather than passed, and the finding says which PHP was measured. Conflicting hints skip | warning; info for plugin mismatch | FS, runtime | 0.1 |
| `config.php.settings` | `WP_MEMORY_LIMIT` in `wp-config.php` below 64 MiB (info). `display_errors`, `memory_limit` and `max_execution_time` from literal `ini_set()` calls in `wp-config.php`, `.user.ini` and `php.ini` in the site root, in that order of precedence: `display_errors` on or `stdout` is a warning (`stderr` goes to the server log and passes); `memory_limit` below 64 MiB and `max_execution_time` between 1 and 29 seconds are info. Skipped when none is set, or when a value could not be read and nothing else was found wrong. The web server's own configuration can override all of these and is not examined, so findings say "likely" | warning; info | FS | 0.1 |
| `config.db.version` | A MySQL or MariaDB release series, from `SELECT VERSION()`, past the end of support its vendor publishes: for MySQL the end of extended support of a long-term series, with Innovation series ending at the next release; for MariaDB the end of community maintenance. A month or quarter given by the vendor counts as its last day. A series older than every one in the table has ended. Percona Server and other forks are read as MySQL. A host may still patch an old series, so the finding says "likely". Skipped when the series is newer than the table, or missing from it (MariaDB 11.3 and 12.0 to 12.2, for which MariaDB publishes no date), and when the version cannot be read | warning ("likely") | DB | 0.2 |
| `config.xmlrpc.enabled` | `xmlrpc.php` in the core directory with no rule denying it in the `.htaccess` of the site root or the core directory: a `<Files>` or `<FilesMatch>` block naming it with `Require all denied` or `Deny from all`, a `RewriteRule` naming it with `[F]`, `[G]` or `R=403`, `404` or `410`, or a `Redirect`/`RedirectMatch` with such a status. The `xmlrpc_enabled` filter only turns off the methods that need a login, so it is not looked for. Rules in the web server's own configuration, as nginx uses, are not visible, so the finding says "likely". Skipped when an `.htaccess` cannot be read | info ("likely") | FS | 0.2 |
| `config.userenum.enabled` | Author archive and REST user enumeration reachable (`--url` mode) | info | HTTP | later |

## Check template for contributors

1. Create `src/Check/Category/<Area>/class-<name>-check.php` implementing `Check`.
   Implement `Runs_Without_Config` instead only when the check reads nothing
   from `wp-config.php`, the database, or a directory `wp-config.php` can move;
   such a check still runs when `wp-config.php` cannot be read.
2. Return `Result::pass()`, `Result::findings(...)`, or `Result::skipped($reason)`.
3. Build every `Finding` with evidence and a fix.
4. Add the row to this file.
5. Add tests: one failing fixture, one passing fixture, and an assertion that
   the fixture contained rows or files to examine.
6. Register the class in `CheckRegistry`.

See `CONTRIBUTING.md` for the full checklist.
